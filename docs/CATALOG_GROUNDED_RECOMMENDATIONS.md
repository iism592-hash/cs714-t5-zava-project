# Catalog-grounded shopping recommendations

The advisor previously required shopping links for every recommended item,
including safety equipment absent from Zava's catalog. The cart then skipped
those nonexistent products and reported a partial bulk add.

The synthesis prompt now distinguishes inventory-backed products from safety
equipment the customer must prepare separately. It forbids prices, stock claims
and shopping links for equipment without an inventory record.

The web streaming proxy independently reads a complete paginated catalog before
rendering commerce links. It buffers complete lines, so a link split across model
tokens cannot briefly appear before validation. Only an unambiguous exact product
name with positive stock and a valid price remains linked. Links use the canonical
product name and current catalog price, including approved offers. Missing items
remain plain-text reminders to source separately. A failed or incomplete catalog
snapshot disables commerce links without claiming the store does not sell them.
Session history stores the checked text. This validates product identity and
price for links; it does not certify all advice generated by the model.

The cart still rechecks exact names and catalog prices. Typed cart confirmation
now awaits that result before displaying the added items, matching button usage.
The browser asset version changes to `catalog-grounding-1`.

Validation: `tests/test_product_grounding.py` covers token fragmentation,
unavailable PPE, corrected prices, zero-price offers, stock, ambiguous names,
catalog failures/pagination and the actual web SSE/session path. Existing Node
cart tests also pass. Live deployment evidence is recorded in `codex_results.txt`.

The deployment overlays these files onto the existing B2C image; unrelated local
managed-identity and infrastructure changes are preserved separately in the
working tree. No catalog products or real discounts are created by this fix.
